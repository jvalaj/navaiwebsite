How it works

From a sentence to a click.

/001 Perceive

Read the accessibility tree

You type a goal, like "Open Notes and create a new note." Nav screenshots the Mac and walks the accessibility tree: buttons, text fields, menus, links, each with an id, a role, a label, and a box.

/002 Reason

Let any LLM choose the next action

The model sees the screenshot and the element list. It answers with JSON, such as click element 12 or type "Hello." It never has to invent a pixel coordinate.

/003 Act

Click, type, and check again

Nav maps that id to the control on screen, accounting for Retina scaling, and performs the click or keystroke. Then it looks again. If the UI did not change, it reuses the tree. If the goal is done, it stops.

Faq's

Understanding Nav

What is Nav? ×
Nav is a computer-use agent for macOS. It turns the model you already use into something that can see your screen, read the accessibility tree, and operate apps for you.
How is the accessibility tree like the DOM? +
A web agent reads HTML: tags, text, and boxes. Nav reads the macOS accessibility tree the same way. Each control has a role, a label, and a location. The model refers to those controls by id. Vision fills in when an app does not expose its tree.
Which models can I use? +
Any of the built-in providers: Claude, ChatGPT, Gemini, or GLM. You can also point Nav at a local OpenAI-compatible server such as Ollama, LM Studio, or vLLM. The agent loop stays the same. Only the model changes.
What can it actually do? +
General computer use on your Mac. Open an app, click a button, type into a field, press a shortcut, scroll, and continue across windows until the goal is finished. It is not limited to one scripted workflow.
Where do actions happen? +
On your Mac. Nav is a desktop app. The model call goes to the provider you select, and the click, type, and scroll happen locally through the real interface.
